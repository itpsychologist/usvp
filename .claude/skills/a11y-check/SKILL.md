# Перевірка доступності

Ціль: 0 порушень axe рівня `serious`/`critical`, Lighthouse Accessibility ≥ 95, решта категорій ≥ 90.

## 1. Підготовка
- Запусти dev-сервер: `uv run python manage.py runserver`.
- Визнач URL сторінок, яких стосувалися зміни, плюс головну (`/`) і EN-версію (`/en/`).

## 2. Автоматичні перевірки
- **axe-core** через Playwright (MCP або `npx`):
  ```
  npx --yes @axe-core/cli http://localhost:8000/ --tags wcag2a,wcag2aa,wcag21a,wcag21aa --exit
  ```
- **Lighthouse** (мобільний профіль):
  ```
  npx --yes lighthouse http://localhost:8000/ --only-categories=accessibility,performance,seo,best-practices --form-factor=mobile --quiet --chrome-flags="--headless" --output=json --output-path=./lighthouse.json
  ```
  Не коміть `lighthouse.json`.

## 3. Ручний чек-лист
- [ ] Навігація лише клавіатурою (Tab / Shift+Tab / Enter / Esc): порядок логічний, фокус завжди видно, немає пасток фокуса.
- [ ] Посилання «Перейти до змісту» працює.
- [ ] Контраст тексту ≥ 4.5:1, великого тексту й UI-елементів ≥ 3:1 (також у режимі високого контрасту).
- [ ] Зум 200% і ширина 320px: без горизонтальної прокрутки й обрізаного тексту.
- [ ] Один `h1`, ієрархія заголовків без пропусків.
- [ ] Усі зображення мають змістовний `alt` або `alt=""` для декоративних.
- [ ] Форми (пошук) мають видимі підписи.
- [ ] `<html lang>` відповідає мові; іншомовні фрагменти позначені `lang`.
- [ ] Анімації поважають `prefers-reduced-motion`.
- [ ] Меню й акордеони мають коректні `aria-expanded` / `aria-controls`.

## 4. Звіт
Коротко перелічи знайдені проблеми (сторінка, критерій WCAG, що виправити) та що вже виправлено.
